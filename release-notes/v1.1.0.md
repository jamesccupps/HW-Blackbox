# HW Blackbox 1.1.0

The hardware's own errors and the drives' health, Windows notifications, times with their time zone, and Home
Assistant as an add-on. The settings and the history carry over.

### New: hardware errors

The CPU, the memory and PCI Express report errors to Windows (WHEA). A corrected one did no harm, but it's the first
sign of a part or a setting on the edge (an overclock, XMP / EXPO, a loose card or riser); a fatal one is a blue
screen. HW Blackbox now records them, and the drives' own errors too: bad blocks, reads and writes retried, a drive's
controller reset, a damaged file system.

- **Diagnose** has a **Hardware errors** check: how many, from which part, and what to do about each (the CPU, the
  memory, a PCIe link).
- **Events** has a **Hardware** group.
- **A power-off report** lists the hardware's error records around it, and names a blue screen's stop code
  (`0x124 WHEA_UNCORRECTABLE_ERROR: the hardware reported an error it couldn't correct...`).
- A board that reports a corrected error every few seconds doesn't flood the records: each kind is written 30 times
  an hour at most, and the next one says how many were left out.

### New: the drives' health

Once an hour, each drive's health as Windows judges it, its temperature, how worn it is, and the errors it has
counted (Windows' storage counters: `Get-StorageReliabilityCounter`).

- **Diagnose** has a **Drives** check: a drive Windows calls unhealthy, errors it couldn't correct (and whether they
  grew this month), worn out, running hot, or the error records of the last week, each with what to do.
- **The Overview's** Disks card shows each drive, and a new **Hardware** card sums it up.
- A drive Windows calls unhealthy is a problem: "back it up now".

### New: notifications

A Windows notification, so you hear of it without opening the page: the PC went off without shutting down, an app
crashed, the hardware or a drive reported an error, or something stopped working. Clicking one opens the page where
it's explained.

- Each signed-in user gets their own, and chooses which on the new **Settings** tab, with **Send a test
  notification**.
- They're rationed: one of a kind every 10 minutes, six an hour. A problem is announced once it has lasted a minute.
  Nothing from before the install is announced.
- They show as **HW Blackbox** (the installer registers the name and its icon with Windows).

### Home Assistant: an add-on, on the Settings tab

Most people don't run Home Assistant, so it's no longer on the Overview. On **Settings → Home Assistant**,
**Set up…** asks Windows for an admin, then a window asks for the address and a long-lived token, tries them, and only
then keeps them. **Turn off…** stops it and offers to delete the token. (From a prompt, as admin:
`python -m hwblackbox homeassistant`, `--off` to turn it off.) An existing setup carries on as it was. The status
gains `last_hardware_error`, `last_drive_error` and `drives`.

### Times with their time zone

Every time in the logs and records now carries its offset from UTC (`2026-11-10T18:23:02-05:00`). Until now, when
daylight saving ended the repeated hour was written twice the same way, and the charts drew it over itself. Older
logs are read in order to tell the two apart. The status's own lines (the last incident, the last power loss) keep
their form, so a Home Assistant automation that watches them doesn't fire because of the update.

### Smaller

- **Crashes are named by their program:** "python.exe (QGIS 3.44.15), in gdal313.dll" rather than "python.exe": a
  `python.exe` can be anyone's.
- **An extra Explorer quitting isn't an incident.** A program that opens a folder or starts another program through
  `explorer.exe` makes an Explorer that hands the job to the taskbar's and quits with exit code 1 (seen when the Ollama
  and LocalCast updaters started their programs). It's on the Events tab, not an incident. The taskbar's own Explorer
  ending, and any crash, still are.
- **The logs are packed** once they're two days old (`.csv.gz`, about a tenth of the size) and read as before: six
  months of history in tens of megabytes rather than hundreds.
- **A row cut off by a power loss** stays on a line of its own: the next row isn't glued onto it.
- **Accessibility:** dark controls, more contrast on the counts and tags, labels for the search boxes, which segment
  is pressed, rows that open as buttons, an alert banner that says what went wrong (not "can't reach" when the page's
  server answered with an error), and charts readable with the keyboard (Tab to one, then the arrow keys).

### Security

From the November review's remaining findings:

- **Each user's folder is theirs alone.** `sessions\` was a folder any user could make folders in, named by user
  name: anyone could make another user's first, write records into it, or read theirs. Now the service makes each
  user's folder as they sign in, named by their account's SID, for that user, admins and the service only; users
  can't make folders there. An older version's folder moves to the new name with its history, if it was made by its
  own user; one someone else made is moved aside.
- **The install is checked before it's put in place.** The installer copies the program into a folder of its own in
  Program Files and checks every file against the manifest while the installed version keeps running. Only the
  build's files are copied: anything else in the release folder (a `.pth` file would have run as SYSTEM) is left out.
  If a file doesn't match, nothing installed is touched. Until now the copy went over the installed program and was
  checked after.
- **The build is tighter.** It checks the packages are the tested versions (`requirements.txt`) and the bundled DLLs
  are the ones shipped (by SHA-256), and copies only the packages the program uses: 1,991 files instead of 2,420.
  This release's Python is 3.12.10.
- A crash record names an exe's path, and any program can write one: HW Blackbox looks up a short path's full name
  only under Program Files, and never a network path.

### Install or update

From 1.0.10 or later: the page offers this version; click **Update**. From 1.0.9 or earlier: download
**HWBlackbox-win64.zip** below, unzip it, and double-click **`Install.cmd`**. An update keeps the settings and the
history. New here? See [Install](https://github.com/jamesccupps/HW-Blackbox#install): it offers the PawnIO driver if
it's missing.
